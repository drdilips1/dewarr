# Initial cover export

September 17, 2026. Implemented for reviewed new imports; this does not complete S04.

## User behavior and authority

The import review includes **Include selected catalog covers in new imports**, enabled by default. Saving the plan freezes each selected work's current catalog-cover URL along with its metadata and naming choices. The saved plan reports the number of selected covers. Disabling the option freezes no cover sources. Plans saved before this feature remain valid without adding artwork retroactively.

Before publication, the worker retrieves and normalizes the selected image. It persists the generated JPEG bytes and their hash in the entry's publication specification before any filesystem publication. A retry uses those bytes even if the provider image or the app's chosen cover has changed. Superseded workers cannot replace preparation evidence. A failed or unsupported cover is recorded as **No cover exported** without preventing the book import; that decision is also retained on retry.

`cover.jpg` is a newly generated independent file in the new item folder. It is never a hardlink to a downloaded image, and media source files are never retagged. The publisher's existing staging, journal, collision and no-replace rules apply to it. Confirmation reports whether ABS selected that exact path and whether its bytes are unchanged. Another selected cover or a later artwork edit does not invalidate correctly confirmed media, trigger replacement, or change overall ownership.

This is initial export, not continuous artwork synchronization. A changed catalog cover does not rewrite existing library art. Cover edits made after publication are left untouched by detection retries and duplicate-import checks. Post-publication crash recovery still uses the strict journal manifest; unexplained changes before database acknowledgement may require review rather than being adopted silently.

## Retrieval and decoding contract

- Entry URLs are HTTPS on `covers.openlibrary.org` or `assets.hardcover.app`, port 443, without credentials or fragments.
- The observed Open Library redirect to an `archive.org/download/olcovers…` image member is supported. Its subsequent `ia<number>.us.archive.org` or `.eu.archive.org` image route must retain the same archive bundle and JPEG member. Arbitrary Archive URLs are not accepted as entry URLs or Hardcover redirects.
- Every hop resolves afresh and requires exclusively public addresses. The connection uses a checked IP with the original Host and TLS server name. Up to four validated addresses can be tried on connection failure, within one 30-second total deadline; partial response bodies are not retried.
- Four response hops maximum; no environment proxy inheritance, provider credentials, forwarded cookies, or compressed HTTP bodies. HTTPX request logging is suppressed for these potentially signed URLs. Errors omit URLs and response content.
- Input is bounded to 8 MiB; supported content types and decoders are JPEG, PNG and WebP. Reject HTML/SVG, animation, invalid/truncated images, tiny placeholders and more than 16 million pixels or an 8192-pixel edge.
- A disposable process decodes, applies orientation, strips embedded metadata, composites transparency onto white and writes a JPEG no larger than 1200 pixels per edge and 512 KiB. It has a 15-second wall-clock limit, 10-second CPU limit and, on Linux, a 1 GiB address-space limit.

These image requests are distinct from source/downloader routing. Image fetches do not supply a MAM route or configure qBittorrent networking. No batch catalog-image crawler is implemented.

## Persistence and verification

Migration `0013_import_covers` adds nullable export evidence to import entries. Generated bytes are base64 encoded in the existing immutable publication specification. Older specifications with no binary sidecars retain their prior receipt fingerprint. Populated cover history prevents a lossy downgrade; use a pre-upgrade backup for rollback.

Evidence:

- Forty cover unit cases cover normalization, routing/redirect bounds, DNS pinning, address fallback, transfer bounds, decoder failure, publication recovery and legacy fingerprints.
- Seven integration cases cover frozen selection, optional failure, crash/retry consistency, external artwork edits, stale workers, explicit omission and downgrade protection.
- Real ABS 2.36.1 ebook and merged-audio application workflows select the generated cover, preserve a later changed image and skip a duplicate import. HTTP image content is synthetic; the decoder, filesystem publisher and ABS scanner are real.
- A separate read-only live request to the documented Open Library cover ID `240727` succeeds through the production fetcher and decoder, including the Archive redirects. Ignored `.local/evidence/cover-live.json` records format, dimensions, size and hash; the external image is not retained or bundled. This proves one route, not comprehensive provider availability.

Remaining work includes version-specific artwork overrides, optional artwork repair, deduplicated image storage/cache, broader live CDN compatibility and the full metadata/ABS-edit recovery matrix. Images occupy up to 512 KiB per prepared entry before base64 overhead; capacity/backup benchmarking remains part of the production gate.

References: [Open Library Covers API](https://openlibrary.org/dev/docs/api/covers), [HTTPX TLS host extension](https://www.python-httpx.org/advanced/extensions/), [Pillow image operations](https://pillow.readthedocs.io/en/stable/reference/Image.html), [Pillow image orientation](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html). The narrow Archive route comes from the observed live redirect, not a claim that arbitrary Archive endpoints are an image API.
