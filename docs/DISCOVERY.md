# Discovery catalog

Discover is the cover-led home for public collections and a reader's own lists. **For you** contains a small default selection, connected personal shelves, pinned collections, and library/provider shelves when available. Customize hides and reorders rows per reader. **Browse** filters books before pagination; **Collections** browses Listopia lists; **Awards** preserves Goodreads' category names for each year; **Your lists** brings followed account lists and saved public collections together.

The bundled catalog includes 12 reviewed genre lists and 282 Choice Award categories for 2011–2025. It needs no provider account for initial browsing. Listopia snapshots contain the first 100 ranked entries for horizontal Discover previews. View all requests the complete list in 40-book batches, fetching current 100-book Goodreads pages on demand and caching them per reader for a day. It is not capped at 100; a failed upstream page leaves loaded books visible with a retry control. Newly loaded entries remain available to native book details and bulk downloads. Source totals may change as readers update Goodreads lists. The snapshot remains marked partial when the source has more. Award snapshots preserve the published results, winner, votes, and source order. 2009–2010 are reported as archive gaps because the source pages are unavailable. We do not synthesize missing nominees. The repository stores identifiers and factual metadata, not review text or cover files. At runtime, Goodreads shelf sync saves validated cover URLs and backfills missing artwork on existing entries without clearing saved covers. Book cards download host-restricted, decoded JPEG artwork through an authenticated local cache: image bytes persist in PostgreSQL for up to a year and browser responses use a private one-day cache. Failed downloads are not cached. API and worker both need restarting for this update; no migration is required.

Adding a public list uses preview → display/tracking options → native collection page. Goodreads personal shelves use the existing private list subscription flow. Hardcover lists remain available through the existing public-list browser and connected reading accounts. Connecting Goodreads uses public shelf/RSS access; it is not Goodreads OAuth. Tracking refreshes membership only and never enables acquisition. Showing a collection and tracking it are separate controls.

## Community contributions

The catalog lives in `services/app/data/discovery/`. Propose curated sources through a pull request:

1. Add a reviewed genre/Goodreads Listopia URL to `seeds.json`. Prefer a focused, broadly useful list with a clear title and stable source ID.
2. Run `uv run python scripts/build_discovery_catalog.py --lists-only` to fetch bounded snapshots. The builder validates source identities and retains previous snapshots on failure.
3. Inspect the resulting JSON: title, genre, ranking, covers, source count, and coverage. Remove a retired snapshot explicitly in the same PR; the builder deliberately does not erase existing data.
4. Include a short explanation of who the collection helps and why it belongs in the defaults. Changing the catalog does not change existing readers' saved snapshots or preferences.

For a new awards year, run `uv run python scripts/build_discovery_catalog.py --year 2026` once final results are published. Use `--refresh` to re-fetch an already bundled year. Inspect `coverage.json` and nominee counts before merging. Historical source category names are preserved; `category_genres` maps them onto the browse filters. Individual category URLs can also be added in the app.

## Storage and operation

Migration `0047_discovery_collections` adds per-reader layouts and collection follows. Deploy API and worker together after the usual backup and migration. Bundled JSON ships with the Python package. The worker checks for due follows every ten minutes; public lists refresh daily and final award snapshots weekly. Requests are bounded, host restricted, and never bypass login/challenge pages. Failed refreshes retain the last usable public snapshot and show a warning. Generation checks prevent paused or obsolete jobs from replacing current state.

New endpoints live under `/api/discovery`: `collections`, `browse`, `layout`, and `personal-list`. Public metadata is read-only until explicitly saved; private account lists continue to use existing list access controls. The catalog does not import all books into the local library. Existing Goodreads bindings display local availability, and visible Goodreads entries resolve through the reader’s connected Hardcover account. Verified title/author or ISBN matches supply full-size covers and open native book details. Goodreads series suffixes are normalized only for individual numbered books. Ambiguous results offer an explicit book choice; disconnected accounts retain larger Goodreads covers and an account connection link. Matching is read-only and does not create library ownership or catalog bindings. The main navigation routes list discovery through **Discover → Your lists**; existing list-management URLs remain available.

Validation: `tests/unit/test_goodreads_discovery.py`, `tests/integration/test_discovery_collections.py`, and `apps/web/tests/discovery-curation.spec.ts` cover parsing/URL restrictions, filtering, account isolation, refresh preservation, and desktop/mobile discovery flows.


Full Listopia browsing uses `GET /api/discovery/collections/{id}?full=true&page=N`; requests without `full` retain snapshot-only pagination for home previews. Cached pages are scoped to the reader and snapshot timestamp in the existing provider cache, so no database migration is needed. Goodreads redirects must retain both list identity and page. Repeated, challenged, or truncated responses fail rather than being stored as a completed list; tied source ranks are allowed. Source filters (`q` and `winners`) remain snapshot-only for Listopia; awards retain their normal filters.
